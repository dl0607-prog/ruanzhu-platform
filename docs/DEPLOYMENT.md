# 多人服务器部署

1. 准备服务器、Docker Compose 和域名；域名 DNS 指向服务器，开放80/443端口。
2. 复制 `.env.example` 为 `.env`，设置至少12位初始管理员密码及域名。服务器保留 `COOKIE_SECURE=true`，仅本机HTTP测试可改为false。
3. 运行 `docker compose -f docker-compose.yml -f docker-compose.server.yml up -d --build`。
4. 查看 `docker compose logs ruanzhu` 确认初始化成功；打开域名登录，创建成员账号。用两个账号验证项目互不可见。
5. 如需AI，设置 LLM_BASE_URL、LLM_API_KEY、LLM_MODEL 后重建容器。密钥仅放服务器.env中。
6. 每次升级前备份持久卷，特别是数据库和截图。停止写入后导出卷备份，恢复时必须同时恢复 data 和 exports；不要把卷或.env上传GitHub。

默认单进程 SQLite，适合小团队；不应直接扩容多个应用容器共享SQLite。未配置管理员密码时启动失败属于预期保护。旧项目首次启动转交初始管理员，迁移前请备份。

后端不信任转发IP头；登录限速按代理地址和用户名计算，多次失败会暂时限制同一账号。Caddy限制单请求25MB，后端限制单文件20MB，ZIP解压总量100MB/5000条目。截图上限5MB。

退出登录会撤销服务端会话，登录会话12小时失效。当前账号由管理员创建，尚无邮件找回密码、MFA及完整账号管理后台。部署到公网前请落实备份和账户运营方案。

验收：未登录API返回401；成员无法访问他人项目及下载；上传代码、人工录入说明书和表单、检查截图、保存人工确认、预检、下载ZIP均成功。AI需使用自己的有效服务凭证额外验收，自动化测试中的模拟LLM不代表线上模型质量。
