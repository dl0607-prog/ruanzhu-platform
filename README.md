# 软著工场

面向多人使用的软件著作权申请材料工作台：账号登录 → 独立项目 → 源码导入 → AI 辅助或人工录入 → 有来源的知识库 → 材料预检与人工核对 → docx/ZIP 导出 → 官网提交与补正记录。

平台不是登记机构，不承诺获证，也不代替官网实名、签章及提交。AI 未配置时，人工录入、预检、截图和导出仍可使用。

## 本机启动

```sh
python3 -m venv .venv
.venv/bin/pip install -r backend/requirements.txt
cp .env.example .env
# 编辑 .env：设置 ADMIN_PASSWORD（至少12位）；仅本机HTTP设置 COOKIE_SECURE=false
./start.sh
```

打开 http://127.0.0.1:8310，以 `.env` 的初始管理员账号登录。在界面“创建账号”中开通成员，每个账号仅能访问自己的项目、源码、截图、报告、导出文件和补正案例。管理员管理公共参考规则，不默认读取成员项目。旧版无账号项目首次启动归属初始管理员。首次启动后修改 ADMIN_PASSWORD 不会重置已创建账号密码。

## 服务器部署

参见 [部署说明](docs/DEPLOYMENT.md)。修复了旧 Dockerfile 的目录层级错误，后端和前端在镜像中处于正确位置。

```sh
cp .env.example .env
# 设置管理员初始密码、DOMAIN（已解析至服务器）、COOKIE_SECURE=true
# 需要AI时再填写LLM服务商配置，不要提交.env到仓库
docker compose -f docker-compose.yml -f docker-compose.server.yml up -d --build
```

Caddy 为域名提供 HTTPS，数据库、截图、导出文件使用持久卷；后端端口仅绑定回环地址。没有服务器与域名时，这一步尚不能形成线上服务。

## 真实材料流程

1. 填软件名称、版本、真实完成日期和著作权人。
2. 上传自有源码 ZIP，依赖目录自动排除；检查是否包含实际核心业务模块。空代码或损坏压缩包不会覆盖已有内容。
3. 在材料生成页使用 AI，或选择“人工录入材料”，录入操作说明书/设计说明书、申请表参考字段等。申请表通过普通表单填写，保存后导出同步使用新值。
4. 上传实际运行截图，与说明书占位名称对应。AI 生成仅是草稿；缺少事实应标为待核实，不虚构开发过程、测试记录或人工贡献。
5. 运行预检。最后确认身份权属、软件与材料、官网与提交文件三项。项目信息、代码或材料发生变化后，既有确认失效；旧材料需重新核对保存或生成。
6. 下载 docx 与材料包；通过打印视图生成 PDF 后逐页检查。当前并未提供服务器自动 PDF 排版引擎，docx/浏览器最终分页需要人工核验。
7. 从 [中国版权保护中心官网](https://www.ccopyright.com.cn/) 进入登记系统，按当前页面要求完成实名、填表、签章和上传。本平台的预填稿不是官网正式申请表。
8. 收到补正后，把通知存入本项目知识库，登记指定截止日期及逐项处理记录，再修改材料、重新预检和官网回复。

## 规则来源与纠偏

内置14条带来源、核验日期和性质的参考项，区分官方规定、官方通知转载及服务商补正经验。详见 [研究记录](docs/research/registration-findings.md)。旧版内置规则会停用，用户案例保留；重复启动不重复插入规则。

删除了无充分官方依据的统一“3000行最低门槛”“功能/目的各500字”“每日3件限制”和“2026-03-15强制AI声明”要求。AI相关关键词不再自动判定材料不合格，不能通过删除署名、许可证或来源标记伪装原创。

## 测试

```sh
.venv/bin/pip install pytest
cd backend
../.venv/bin/python -m pytest tests -q
```

覆盖账号与项目隔离、跨站请求、登录限速、人工材料到导出完整流程、修订失效、知识库升级，以及原有文档引擎与源码上传回归。

## 当前边界

尚未完成真实服务器部署、真实 LLM 服务联调或版权中心正式申请。没有运行源码的沙箱，也不能自动判断权属、原创性或软件真实运行效果。源码样本发送到所配置的 LLM 服务商；配置前应确认该服务允许处理这些材料。此版本适合受信任的小团队部署试用，公网运营还需账号恢复、配额、审计和备份运营流程。
